КОНСТРУКТОР БОЁВ УРОВНЯ (построение, не проверка). Создан 2026-09-19 при переработке уровней 1-10.
Проверка готовности уровня — ТОЛЬКО scripts/combat-data-inventory.js --check=N (правила, часть А).
Запуск: node scripts/level-builder/run.js N   (читает designN.js, собирает боевые данные, пишет lvlData/gameDataN.js,
затем сам вызывает --check=N и печатает вывод). designN.js — авторский дизайн: профиль, скаляры, семейства приёмов
по боссам (fam.js), подписи. compose.js подбирает скорости/высоты под задуманный порядок и ритм и отсеивает
кандидатов, совпадающих по «решению игрока» с другими уровнями. diagreal.js — диагностика на реальном движке
(устойчивость порядка прилёта при speedVariance и стиле движения); не заменяет --check.

Перед первой сборкой run.js сохраняет исходный gameDataN.js в scripts/baseline/, если базы ещё нет.
Существующую базу не заменяет: --check обязан сравнивать давление с исходным боем по А7.3.
Окончательная сверка исполнения: verify-level.js N путь_к_исходному_снимку; он вызывает реальные функции игры.
dmgcheck.js N [путь_к_исходному_снимку] сравнивает средний урон по слотам; без снимка берёт git HEAD.

ЦЕПИ (уровни 41+; поддержка добавлена при доводке 41): design содержит attackChains:true,
фирменное комбо — isChain:true и shotDelayMs не меньше требования раздела 13.7.
Все атаки такого комбо связаны в одну цепь; обычные атаки задаются отдельными комбо.
author.js подбирает для цепей только времена режимом G, передавая свойства комбо в fitlib.
combo-model передаёт blockOrder, player-model считает обязательный порядок отбивания головы,
а инвентарь проверяет невозрастание фактических скоростей во всех вращениях variance.
Проверка функций движка: node scripts/chain-mechanics-test.js. Числовые пороги не изменены.

УТОЧНЕНИЯ ПО ДОВОДКЕ 42–54 (2026-11-05; пороги не меняются):
 - Формы, стороны и скорости пишет автор по образу. Старые генераторы семейств выше не заменяют проект боя;
   author.js калибрует только времена/паузы заданной формы, готовность — обязательные проверки и описание после сборки.
 - В design флаги называются sig и open (не signature/openingOrder). Последние имена появляются в gameData.
   isChain, shotDelayMs и minPhase сохраняют свои имена. verify-level проверяет реальное знакомство цепью второй волной.
 - shotGapsMs НЕ прибавляется к базовому шагу: каждый промежуток равен max(базовый шаг, явно заданный gap).
   Для 720 мс между флангами суммировать эти реальные промежутки в каждой фазе. Например 620 и 100 при шаге 103
   дают 723 мс, а не 926. Расписание рассчитывать моделью, не отдельной копией формулы.
 - Укорачивание telegraphMs само по себе не доказывает уменьшения запаса: sequentialSlack прибавляет телеграф
   и к прилёту, и к доступности цели. Когда прицел ждёт появления, разность не меняется. Трудность создаёт задача обхода.
 - Для wave синтаксис формы: x/скорость#амплитуда,частота,фаза!gap — блок волны перед !gap.
 - Верификатор сравнивает запас также по настоящим Enemy.update. Пара с разницей в несколько миллисекунд может
   поменяться местами при дискретном исполнении и сорвать блок, даже когда --check зелёный. Развести конкретные
   прилёты в design, снова run.js и полная сверка. Дополнительно осмотреть фактические полосы --level, особенно L x>25.
 - При провале запаса verify-level.js собирает все такие случаи до конца прогона и затем падает одним списком.
   Это помогает исправлять несколько близких прилётов за один проход; порог 60 мс и расчёт не меняются.
 - Для уровней >=25 verify-level также отклоняет выход из реальных полос А11.8: L x=4..25, K/R x=69..94.
   Сдвиги уникальности на x=26..68 и x>94 нельзя принимать по зелёному расчёту полёта; править design и повторять конвейер.

БАРРИКАДЫ (ввод области VI, уровень66, 2026-11-08; правила А12):
 - Комбо в design: barricades:{0:{hits:3,rush:2.2,y:5}}, tight:false. Ключ 0 — индекс бита,
   не индекс способности. В beats автор задаёт x/скорость; y баррикады берётся из barricades.
   Её желаемый @прилёт не подменяет явную геометрию: реальный прилёт = ожидание + полёт рывка.
 - Конструктор сохраняет barricade:true, barricadeHits, barricadePauseMs=hits*400 и множитель рывка;
   обычная и баррикадная атаки одной геометрии не сливаются в реестре. Не совмещать с isChain.
 - combo-model учитывает стойку и рывок без стиля босса; player-model — каждый удар, перенос и
   до одного кадра 60 Гц на повторный удар. fitlib также сохраняет свойства баррикад в оценке;
   не оценивать новую комбинацию массивом из одних x/y/скорость, потеряв поля счётчика.
 - Минимальный маршрут первого знакомства: срочные угрозы, затем полный разбор. Модель не
   предполагает бесплатные промежуточные удары и не доказывает обязательные прерывания/возвраты.
 - run.js дополнительно запускает barricade-workload-audit.js: 45000 выборов настоящего селектора,
   все попадания, реальные периоды волн, без оценочных +2500 мс старого сравнительного отчёта.
   Превышение потолка откатывает кандидат. Старое давление «до→после» тоже обязано пройти.
 - verify-level для66 проверяет передышку после всех серий, для баррикад — минимум600мс;
   для66+ отдельно реально запускает все допустимые серии через executeBossEvent и проверяет
   полный состав, фактический счётчик HP баррикад и цепи. Ручную игру это не заменяет.
 - Регрессия механики: node scripts/barricade-mechanics-test.js — попадания/криты/ранение,
   покадровый кулдаун60/120Гц, неподвижность, рывок, пауза и финальный эффект отбоя.
 - Опциональный combatHeader в design заменяет устаревшие вводные комментарии через конвейер,
   не меняя защищённые данные. Художественный протокол AGENTS.md применяется отдельно.
