КОНСТРУКТОР БОЁВ УРОВНЯ (построение, не проверка). Создан 2026-09-19 при переработке уровней 1-10.
Проверка готовности уровня — ТОЛЬКО scripts/combat-data-inventory.js --check=N (правила, часть А).
Запуск: node scripts/level-builder/run.js N   (читает designN.js, собирает боевые данные, пишет lvlData/gameDataN.js,
затем сам вызывает --check=N и печатает вывод). designN.js — авторский дизайн: профиль, скаляры, семейства приёмов
по боссам (fam.js), подписи. compose.js подбирает скорости/высоты под задуманный порядок и ритм и отсеивает
кандидатов, совпадающих по «решению игрока» с другими уровнями. diagreal.js — диагностика на реальном движке
(устойчивость порядка прилёта при speedVariance и стиле движения); не заменяет --check.

РАБОЧИЙ ПРОЦЕСС ДЛЯ УРОВНЕЙ >= 25 (2026-09-26, после жалобы «ур.25 слишком лёгкий»; проверка А9.7 меряет ТИПИЧНЫЙ запас, а не худшее вращение):
 1. Формы комбо (стороны/скорости) пишет автор В РЕАЛЬНЫХ ПОЛОСАХ: левый кластер L x 6..25, правый центр K x 69..71, фланг R x 72..94 (см. правила А11.8:
    x 27..40 боссом сдвигается на 16..24, «центральной» полосы x=30 нет). Занятость геометрии: freek.js N enemK (ключи x/y/скорость по полосам), freemap.js, freex.js.
 2. Подбор времён по ТИПИЧНОМУ запасу: план-файл на босса (формат v2: «@id ф1/ф2/ф3» цели + пул форм), затем
      BESTOF=1 SIDEREG=/tmp/sidereg.txt FITOPTS=0,300,450,600 bash plan.sh N /tmp/eK.txt      (FITTYP=1 включает plan.sh; сначала: node sidereg.js N /tmp/sidereg.txt <уже готовые роли>)
    fitlib строит комбо в контексте конвейера (nudgeScalars + занятые ключи + порядок a..h, settle() ищет свободный ключ по высоте y 5..9), поэтому подобранное = построенному.
 3. Быстрые вспомогательные: probe.js/pprobe.sh (одна форма без фиксации), explore.js (почему форма отвергается), chk.js (оценка готовых битов), rotview.js (запас по вращениям),
    sides.js (строки сторон и дубли между боссами, А10.1), typslack.js (типичный запас по уровням), logslack.js <журнал> N (реальный запас против прогноза после боя).
 4. applyfit.js N файл -> design; run.js N -> --check (там же А9.7). Если не сходится — правится форма/цель, а не пороги.

СПЕЦ-УПРАВЛЯЕМЫЙ ПРОЦЕСС (уровни 26-29, 2026-10-03) — быстрый путь для следующих уровней:
 1. Шапка: `hdr.js N patch.json` (пара timeNextBoss/bossInterval, тройка maxActive, speedMultiplier/speedVariance/delay0/delay1 боссов). Правила выбора: delay[0]≈150-175 (иначе 5-6-атак. комбо не влезают в разброс 1000/1600 мс), delay[1] 5600-7100 (потолок давления А7.6),
    speedVariance узкий (ширина 0.06-0.16) — главный рычаг «типичного запаса» и ступеней лестницы А9.7; в design добавить `damageByClass`+`damageClassOverride` или `damageTiers` (проверка `dmgcheck.js N`, `dmgpick.js N`).
 2. Спецификация `spec.json` для mklvl.js: по боссу mode (LK/KL/LKs/KLs/LKt/KLt/LLK/KLL/LKK/KKL), lens[8] (≥4, мультимножество свободно: `freestruct.js N enemK 4 6 34 40 8`; drift — безякорные ≤4, якорные ≤5), speeds, Kspeeds (скорости K-токенов), anchors/anchorX, targets, shifts [0,-1,1],
    idModes/idSpeeds/idKspeeds/idOpts (точечно по комбо), Ks (список x полосы K; 76..88 — полоса П для боссов с итоговой скоростью <18). Оценка профиля полёта до подбора: `shareest.js N spec.json` (А10.3: доли «средних» полётов боссов должны отличаться ≥0.125); свободные ключи K/L: `freek.js`, `freex.js`.
 3. Подбор: `runsome2.sh N dir "роли:asym …"` (FITMONO=2 в окружении) или `runtail.sh` (база plan_some_N_base.txt + реестр сторон из regfromplan.js); сводка: `applyN.sh N base.js plan.txt`; перебор шума: `tryloop.sh`/`tryloop2.sh`.
 4. Остатки: повторы геометрии — `dupfind.js`, `fixdup.js N enemK` (сдвиг прилёта → другой y) / `fixx.js`; разброс >1600 — `nudgeat.js N enemK id мс from`; диагностика «НЕТ» — `whyfail.js`; полёты по атакам — `flights.js`; запас по комбо — `combotyp.js` (приблизительно).
 5. Тексты identity/trick — `settext.js N файл.json` по итоговым комбо f/g/h; `finish.sh N` — итоговая сводка (check, давление, запас, урон).
